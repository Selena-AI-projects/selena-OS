## 1. Сертификат studio.selenasystems.com

**Действие.** В панели DNS-провайдера проверить записи **на имени `studio`** —
нет ли рядом с CNAME чего-то ещё: `A`, `AAAA`, `TXT`, собственной записи `CAA`,
или проксирования (в Cloudflare — оранжевое облако вместо серого).

**Почему.** DNS в порядке: Railway видит `CNAME studio → iu5dnw7q.up.railway.app`
со статусом `PROPAGATED`. Но сертификат больше суток стоит в
`VALIDATING_OWNERSHIP`, и Railway не сообщает причины — `errorMessage` пуст.

**Что уже исключено.** `os.selenasystems.com` живёт в той же зоне, на том же
сервисе, и его сертификат **валиден**. Значит запрета на уровне зоны нет: Let's
Encrypt для `selenasystems.com` уже выдавал сертификат. Причина — в чём-то, что
относится именно к имени `studio`.

**Что пробовали.** Домен сняли и добавили обратно через агента Railway, чтобы
перезапустить выдачу. Результата нет: идентификатор домена остался прежним, цель
CNAME та же, статус сертификата не изменился — то есть настоящего пересоздания не
произошло и новый заказ не стартовал. Прикладной сервис при этом не пострадал:
после раскатки изменений пул к базе поднялся штатно.

**Что ещё исключено.** Подложить корневой сертификат Supabase и включить проверку
обратно (это сняло бы блокер 2, а не этот) — отвергнуто: сертификат нашёлся только
в двух посторонних репозиториях, а доверенный корень из непроверенного источника
хуже нынешнего состояния. Прямой доступ к DNS из среды исполнения закрыт сетевой
политикой, поэтому увидеть записи на имени `studio` можно только из панели
провайдера.

**Продолжится после.** Проверка входа, выхода, обновления сессии и callback на
новом адресе; `os.` при этом не трогается и продолжает работать.

## 2. Перевод DATABASE_URL Aether на пулер Supabase

**Действие.** Supabase → Project Settings → Database → **Connection pooling**,
взять строку с хостом вида `aws-…pooler.supabase.com` и заменить ею
`DATABASE_URL` в переменных Railway-сервиса Aether. **После этого** удалить
`AETHER_DB_SSL_INSECURE`.

**Почему.** Проверка сертификата базы сейчас выключена: с сертификатом прямого
хоста Supabase она не проходит, и сервис поднят временным режимом. Улучшение,
ради которого правка делалась, выключено ровно там, где должно защищать.

**Порядок важен.** Удаление флага до смены строки подключения гарантированно
роняет пул — это уже происходило дважды за сессию, оба раза с одинаковым
`SSLCertVerificationError` в логе.

## 3. Перевыпуск секрета моста

**Действие.** Заменить `SELENA_AETHER_BRIDGE_SECRET` у сервиса `receiver` и
`CONTROL_ROOM_BRIDGE_SECRET` у Aether. Обе стороны принимают список через
запятую: поставить новый первым, старый вторым, дождаться успешной доставки,
затем убрать старый — простоя не будет.

**Почему.** Владелец попросил выполнить перенос самостоятельно, а прочитать уже
установленное значение через API нельзя — оно скрыто. Поэтому значение было
сгенерировано в сессии и прошло через её протокол. Это секрет подписи, не
доступа к данным: им можно подделать событие для staging-приёмника, но нельзя
ничего прочитать.

## 4. Ключи подписи для сервисов gateway и scanner

**Действие.** Создать ключевую пару подписи релизов и учётные данные хранилища,
задать их переменными сервисов и создать сервисы `gateway`, `scanner`, `worker`
в проекте `selena-os-staging` (имя сервиса выбирает стадию сборки).

**Почему это не сделано исполнителем.** Приватный ключ подписи релизов
существует ровно затем, чтобы им владел один компонент. Сгенерировать его в
сессии — значит записать его в протокол сессии, что противоречит смыслу ключа.

**На доказательства не влияет.** Gate 7 и Gate 8 закрыты тестами и pgTAP на
настоящей базе; отсутствие этих сервисов не оставляет ни одного непроверенного
утверждения ТЗ.

## 5. Проверка восьми разделов Control Room в браузере

**Действие.** Открыть `https://web-production-6cb6b.up.railway.app` и пройти
восемь разделов.

**Почему не сделано исполнителем.** Сетевая политика этой среды не пропускает
`*.up.railway.app`: запрос отклоняется на прокси. Разделы проверены живым
запуском приложения на настоящей мигрированной схеме — но не на развёрнутом
контуре и не глазами.
